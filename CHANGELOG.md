## [2.2.0] — Unreleased

### Overview

Version 2.2.0 is primarily a **performance release**. The headline gains come from two largely independent strands that compound where they overlap:

1. **Mathematical: a new analytical decomposition for the underlying sums.**

   Three core quantities underlie the closed-form expectation-tensor calculus: the **inner product** $\langle T_x, T_y \rangle = \int T_x T_y \, \mathrm{d}z$ between two tensors (which underlies cosine similarity, windowed similarity, and Rényi-2 entropy); **point evaluation** $T(q)$ of a single tensor at a query (a sum of Gaussian-kernel contributions, one per source $r$-tuple — no integration involved, since $T$ is already the density); and **total mass** $Z = \int T \, \mathrm{d}z$ of a single tensor (which converts $T$ to a probability density via $T/Z$ and appears in the denominator of Rényi-2 entropy and other normalised quantities). All three reduce to sums over slot-tuples: a double sum (one $r$-tuple per side) for the inner product, a single sum for the other two. v2.0 / v2.1 already evaluated all three analytically — for the inner product via *Bulger's method*, for the others via an explicit centres-array route. v2.2 adds a new decomposition of these sums, **the Möbius method**, that scales far better at high $r$ and high $K$ and uniformly covers all three.

   **Bulger's method** (v1, carried unchanged into v2.0 / v2.1) is specific to the inner product. It organises the slot-tuple sum by taking combinations on one side and permutations on the other, exploiting the within-tuple multinomial symmetry to avoid enumerating equivalent orderings. The asymmetric combinations-vs-permutations organisation requires two sides to be present, so the method does not extend to point evaluation or total mass.

   **The Möbius method**, new in v2.2, is a different decomposition that applies uniformly to all three quantities. The slot-tuple sum is rewritten via Möbius inversion on the partition lattice: the distinct-index constraint becomes an alternating sum over set partitions of the slot indices, with each partition's term factorising across its blocks. For the **inner product** specifically, the partition decomposition combines with **orbit collapse** under the joint slot-permutation symmetry — many partition-pairs are redundant in the sense of contributing identically to the sum, so each redundant family is summed once with a counted multiplicity rather than walked term-by-term. This collapses the $B_r^2$ partition-pair count down to $|\Omega_r|$ orbit equivalence classes (4, 10, 33, 92, 306, 948, 3210 for $r = 2, \ldots, 8$, versus $B_r^2$ as large as $\sim 1.7 \times 10^7$ at $r = 8$). For **point evaluation** and **total mass** there is only one side, so no joint symmetry to exploit and no collapse to perform; cost scales with the bare partition count $|\Pi_r| = B_r$.

   The underlying inclusion-exclusion technique itself has a longer history in MPT: it was first published in Milne et al. 2011 — framed there as inclusion-exclusion rather than as Möbius inversion on the partition lattice (the two are equivalent formulations) — and has been used in the toolbox since v1 for *numerical* computation of discrete tensors. What is new in v2.2 is its application as a closed-form *analytical* decomposition (no discretisation grid involved), its combination with orbit collapse for the inner product, and its uniform extension across all three core quantities.

   **How the Möbius and Bulger methods relate.** For the **inner product** they are alternative decompositions of the same analytical integral. On any given inner-product call the dispatcher picks one and computes the value via that decomposition; the two are not combined within a single call. This exclusivity is pragmatic, not mathematical — both methods already exhaust the same underlying slot-permutation symmetry, just along different routes, so there is no natural way to combine them that would gain over picking the better of the two. Each has a different cost-scaling profile: Bulger's method has essentially no per-call fixed overhead beyond the slot-tuple loop; the Möbius method carries fixed per-call overhead (orbit-table lookup, $|\Omega_r|$ tensor contractions) that must be amortised over the savings from orbit collapse. Bulger's method therefore tends to win at small $r$ and small $K$ (short slot-tuple loops, Möbius's overhead doesn't pay off); the Möbius method wins decisively at large $r$ or large $K$. The cost-model dispatcher in strand 2 picks the cheaper of the two per call. For **point evaluation** and **total mass** Bulger's method does not apply, so there is no two-decomposition choice; v2.2's Möbius method here is an *efficiency alternative* to v2.1's centres-array route — same analytical value, computed without materialising the explicit $r$-tuple centres array, which matters most in the large-$K$ / high-$r$ regime where that array would dominate memory.

   The strand also includes the **ragged-K hybrid** for variable-cardinality MA inner-product inputs (a per-event safe/unsafe partition with an exact direct-enumeration fallback for unsafe events).

2. **Computational: dispatching, kernel precision, kernel truncation, and batching refinements.** A per-call cost-model dispatcher (with a timing-probe fallback for indeterminate SA cosine-similarity regimes) selects whichever decomposition is faster for each call. Two new kernel-evaluation controls — `truncation_sigmas` (skip Gaussian contributions beyond $k$ standard deviations from a centre) and `kernel_precision` (`'single'` instead of `'double'` for the kernel matrix multiplication; ~2× speedup, ~7 sig fig precision) — apply to the centres-path consumers (eval, cos-sim, entropy) at user request and roughly compound with the mathematical-strand gains. Set per call or globally via the new toolbox-wide defaults API (`mpt.set_default` / `mptDefaults`). **Lazy density-struct construction** in `buildExpTens` is also part of this strand: expensive density fields (`U_perm`, `wJ`, `V_comb`, `wV_comb`) are deferred until a consumer needs them — most strand-1 consumers now don't. Finally, **several batching refinements** replace v2.1 sequential per-item loops with grouped contractions: K-grouped direct enumeration for unsafe-event pairs in the MA inner product, a dedup-and-batch rewrite of `tensorHarmonicity`'s batched mode, and vectorised u-grid handling in the Möbius relative-mode evaluator. Each is detailed in the corresponding section below.

v2.2 also exposes **Rényi-2 differential entropy** $H_2 = -\log_b \langle T, T\rangle / Z^2$ as `method='renyi2'` on `entropyExpTens`. The analytical route was conceptually available in v2.0 / v2.1 (it requires only the inner product and total mass, both already analytical); v2.2 wires it up as a user-facing option and gains efficiency at high $r$ / $K$ via the Möbius method. **Shannon differential entropy** has no closed form in any version and is unchanged — `method='shannon'` continues to use a numerical grid.

Additional improvements outside the two strands: **`bindEvents`** accepts $K_{a, n} > 1$ input, unblocking polyphonic-binding analyses with multi-slot attributes at the source. A new pre-tensor preprocessing primitive **`translateEvents` / `translate_events`** translates every value of every attribute in selected groups by a per-group offset (modulo $P$ for periodic groups; structural no-op on relative groups); this is the pre-tensor route to sliding-comparison along an attribute axis, complementary to the post-tensor `windowedSimilarity`, and handles multi-slot attributes ($K_{a, n} > 1$) without ambiguity since every slot translates by the same offset.

The release is additive: existing v2.1.0 calling conventions are preserved at the floating-point level for the default routing in standard regimes. The new method choice is exposed via a `method` keyword on `cosSimExpTens`, `evalExpTens`, and `entropyExpTens` (accepting `'auto'`, `'bulger'`, `'mobius'`, plus `'centres'` for eval and `'direct'` for small problems); `'auto'` is the default and matches v2.1 numerical behaviour on standard inputs. The kernel-evaluation controls default to no truncation and double precision (i.e., the v2.1 numerical behaviour) and only activate when the user opts in.

**Terminology used throughout.** *SA* = single-attribute (one density coordinate per event, e.g. pitch alone); *MA* = multi-attribute (multiple coordinate axes per event, e.g. pitch + onset time). A *multi-attribute expectation tensor* (MAET) is a density built from MA inputs. *Tensor order* $r$ (or $r_a$ for attribute $a$) is the number of slots in each event's ordered-tuple expansion (e.g. $r = 3$ for triadic interval analysis). For each event $n$ and attribute $a$ the *effective slot count* $K_{\text{eff}, n, a}$ is the number of non-NaN entries; the *attribute width* $K_a$ is the constant maximum over events. *Ragged-K* inputs are those where $K_{\text{eff}, n, a}$ varies across events $n$ (e.g. a sequence mixing dyads, triads, and tetrads), so trailing NaN entries pad each event to the common width $K_a$. *Safe* on attribute $a$ for event $n$ means $K_{\text{eff}, n, a} - r_a \ge 2$ (sufficient slot margin for the Möbius method's alternating partition sum — the inclusion-exclusion sum over set partitions of an $r$-tuple, with alternating signs derived from the Möbius function on the partition lattice — to retain precision); *unsafe* means $K_{\text{eff}, n, a} - r_a < 2$, where the alternating-sum cancellation would corrupt the result and a direct ordered-tuple enumeration is used instead. The *Bell number* $B_r$ is the count of set partitions of an $r$-element set ($B_2 = 2$, $B_3 = 5$, ..., $B_7 = 877$, $B_8 = 4140$); orbit-table size scales with $B_r$ and dominates the build cost beyond $r = 8$. *Inner product* (abbreviated *IP* throughout) refers to $\langle T_x, T_y \rangle$. *Canonical-form deduplication* refers to the batched-input optimisation introduced in v2.1: rows that are symmetry-equivalent (e.g. permutations of the same slot multiset, transpositions in relative mode) are reduced to a canonical key, computed once, and the result mapped back to all matching rows. *ULP* = "unit in the last place", the smallest representable spacing in floating-point — a few-ULP difference between two computations is the order of bit-level noise from accumulation reordering and is invisible above three or four significant figures.

### Added — Möbius method (and Bulger's method retained)

- **`method` keyword on `cosSimExpTens`, `evalExpTens`, `entropyExpTens`.** Accepts `'auto'` (default), `'bulger'` (the v2.0 / v2.1 inner-product decomposition; IP-only), `'mobius'` (the new partition-decomposition method, with orbit collapse applied in the IP case), `'centres'` (eval only, the explicit centres-array path), and `'direct'` (small problems where direct enumeration beats both). The `'auto'` setting routes via a per-call cost model that considers $r$, per-attribute $K_a$, event counts, $\sigma/\text{period}$ for periodic-relative groups, and (for MA) the per-attribute safe/unsafe partition. For SA cosine similarity, the dispatcher additionally uses a **timing probe** when the cost-model pre-screen is not decisive (i.e., when neither method's estimated cost dominates the other by ≥10× at the call's parameters): on a small subset of the workload the dispatcher times each candidate method and routes the full call accordingly. The probe-based path is future-proof against incremental optimisations on either side (gains automatically reflected) and replaces the older purely-analytical heuristic for the cos-sim path; the eval dispatcher retains the analytical form since the centres path is cheap enough that probing adds more overhead than it saves. Backward compatibility: at default settings on standard inputs the dispatcher's chosen method produces v2.1.0-equivalent results to floating-point tolerance (a few ULP differences are possible where the probe selects Möbius and the v2.1 default was Bulger, since the two are mathematically equivalent but accumulate in different orders).

- **Pre-built orbit tables for $r \in \{2, \ldots, 8\}$.** Möbius coefficients, partition catalogues, and contraction edge lists are pre-built and shipped in both languages (Python `.pkl`, MATLAB `.mat`); at runtime the Möbius method looks up the table for the given $r$ and contracts, with no enumeration cost paid per call. The shipped maximum is exposed as `_ORBIT_R_MAX_SHIPPED = 8` (Python) and the matching `% _ORBIT_R_MAX_SHIPPED` boundary in MATLAB; the cost-model dispatcher consults it to route away from Möbius at $r > 8$ so users don't pay an unexpected on-demand build cost on first call. Wheel/sdist builds carry the seven shipped pickles via the new `[tool.setuptools.package-data]` block in `pyproject.toml`. Bell-number growth makes higher-$r$ tables expensive: $r = 8$ is 1.65 MB and roughly 3 minutes to build; $r = 9$ would be ~3 MB and ~80 minutes. Users wanting Möbius at $r > 8$ opt in by accepting the build cost on first call (subsequently cached on disk under `~/.mpt/orbit_tables/` or `MPT_CACHE_DIR`); a cost-preview helper prints estimated build time and Bell-number scaling context before the build begins, suppressible via `MPT_NO_BUILD_WARN=1`. A hard cap at $r = 12$ remains for the build path.

- **`cancellationThreshold` keyword on `cosSimExpTens`.** Default `1e-12`. Guards the Möbius method's alternating partition sum against catastrophic cancellation: if the worst-case cancellation ratio across orbit terms drops below the threshold, the dispatcher falls back to Bulger's method. The same threshold gates the Möbius path's three-layer guard for SA cosine similarity (cross-cancellation, corruption, severe ratio).

- **`+mobius` package (MATLAB) / `_mobius.py` module (Python).** Houses the Möbius-method implementation: `innerProductOrbit`, `innerProductOrbitPwBatched`, `innerProductOrbitGrid`, `evalOrbitAbs`, `evalOrbitRel`, `totalMassAbs`, `totalMassRel`, `getOrbitTable`, `buildOrbitTable`, `canonicalForm`, `contract`, and supporting partition / set-partition / contingency-table enumerators. All public-facing operations on densities continue to dispatch through the high-level wrappers (`cosSimExpTens`, `evalExpTens`, etc.); the module is internal but documented for users wanting to understand or extend the machinery. (The legacy `'orbit'` naming inside this module reflects its origin and is retained as an internal label; the user-facing API uses `method='mobius'`.)

### Added — Kernel-evaluation controls (truncation and precision)

These controls govern how the dense Gaussian-kernel matrix is computed in the "centres path" — the path used by `evalExpTens`, `cosSimExpTens`, and `entropyExpTens` whenever the dispatcher selects the explicit-centres-array evaluation strategy (every $r$-tuple in the source cartesian product is materialised as a Gaussian centre, and each query point is evaluated by summing kernel contributions from all centres). The Möbius method uses neither control: it evaluates the same density analytically without forming the centres matrix.

- **`truncation_sigmas` (Python) / `truncationSigmas` (MATLAB).** Type `float`, default `math.inf` / `Inf` (no truncation, exact v2.1 behaviour). When set to a finite positive value $k$, the Gaussian kernel contribution from each centre $\mathbf{c}$ to each query $\mathbf{x}$ is skipped whenever the Mahalanobis distance $\|\mathbf{x} - \mathbf{c}\|_Q$ exceeds $k \sigma$, equivalently whenever the kernel value drops below the floor $\exp(-k^2 / 2)$. ($Q$ is the kernel's inverse-covariance metric; for an isotropic Gaussian $Q = I/\sigma^2$ and the test reduces to $\|\mathbf{x} - \mathbf{c}\|_2 > k\sigma$.) The skip is implemented as a grid-bucket spatial index that avoids forming the dense kernel matrix for the discarded entries, saving the dominant `exp` and matrix-multiply cost on values that would round to negligible contributions anyway. Typical settings: $k = 6$ retains a relative kernel-floor of $\exp(-18) \approx 1.5 \times 10^{-8}$ (numerically indistinguishable from full double precision for cosine similarity); $k = 4$ retains $\exp(-8) \approx 3 \times 10^{-4}$ (visible but bounded perturbation; trades roughly 4× speedup at large $K$ against a fourth-decimal-place change in similarity). Affects all centres-path consumers (eval, cos-sim, entropy) in both SA and MA modes.

- **`kernel_precision` (Python) / `kernelPrecision` (MATLAB).** Accepts `'double'` (default) or `'single'`, the latter casting the kernel-matrix arithmetic to `float32` for a ~2× speedup at the cost of approximately 7 significant figures of precision (vs approximately 15 for double). The cast applies only to the kernel matrix and its immediate matrix multiplication; density coordinates and the final summation in cosine / entropy are preserved at full double precision. Recommended for large-$K$ eval and centres-path cos-sim at scale, where the user is interested in similarities to three or four significant figures and the speed-up is substantial.

- **Toolbox-wide defaults.** A new defaults module exposes `mpt.set_default`, `mpt.get_default`, `mpt.get_defaults`, and `mpt.reset_defaults` in Python; MATLAB exposes the same functionality via `mptDefaults`: `mptDefaults` (no arguments) returns a struct of current values, `mptDefaults('name')` returns one value, `mptDefaults('name', value, ...)` sets one or more values and returns the previous values for save-and-restore idioms, `mptDefaults('reset')` returns to factory values. Per-call kwargs always override defaults. Defaults persist within a single Python process (not across processes) and within a MATLAB session (not across `clear all`). Factory defaults are `truncation_sigmas` / `truncationSigmas` $=$ `Inf`, `kernel_precision` / `kernelPrecision` $=$ `'double'` (i.e., the v2.1 behaviour), and `show_hints` / `showHints` $=$ `True` (see below). The default-mode bypass shortcuts out the v2.2 feature path when both kernel-evaluation defaults hold, so v2.1 callers see byte-exact v2.1 numerics with no overhead.

- **One-shot informational hint on first kernel-matrix construction.** The first time the user runs a calculation that constructs a kernel matrix with both `truncation_sigmas` and `kernel_precision` at their factory defaults — i.e., the v2.1-compatible regime, which leaves performance on the table at scale — a short tip is printed pointing to the `mpt.set_default(truncation_sigmas=6, kernel_precision='single')` / `mptDefaults(...)` opt-in. The hint fires once per session, and self-suppresses if either control has been changed (per call or globally), if the user has set `show_hints` / `showHints` to `false`, or if it has already fired. Affects functions that build a kernel matrix: `evalExpTens`, `entropyExpTens` (Shannon), `spectralEntropy`, `templateHarmonicity`, `virtualPitches`, and `cosSimExpTens` when routed to Bulger's method. Does not fire on Möbius-method calls (which bypass kernel-matrix construction entirely). Permanently disable via `mpt.set_default(show_hints=False)` / `mptDefaults('showHints', false)`.

### Added — Rényi-2 differential entropy

- **`method='renyi2'` on `entropyExpTens` / `entropy_exp_tens`.** Computes $H_2 = -\log_b(\langle T, T\rangle / Z^2)$ in closed form via the Möbius method's inner product for $\langle T, T\rangle$ and the Möbius method's total mass for $Z$. SA paths use `mobius.orbitInnerAbsSA` / `mobius.orbitInnerRelSA` and `mobius.totalMassAbs` / `mobius.totalMassRel`. MA paths factorise $\langle T, T\rangle = \sum_n \prod_a I_a^{(n,n)}$ via the per-attribute IP matrix and likewise use a per-event total-mass product for $Z$. The default remains `method='shannon'` (numerical Shannon entropy on a discretised grid), so existing callers see no behavioural change. `r=1` rel returns 0 by convention (0-D relative space; constant density), matching the spec; `r=1` abs uses a direct kernel-sum branch since the orbit table is undefined at $r=1$. `normalize=True` with `method='renyi2'` raises `NotImplementedError` — the natural normaliser $\log_b(V)$ yields a $(-\infty, 1]$ range rather than Shannon's $[0, 1]$, so a uniform normaliser would be misleading; resolving the normaliser API is left for a follow-up release.

### Added — Ragged-K hybrid for MA Möbius inner product

- **Per-event safe/unsafe partition in the MA per-attribute IP matrix.** Replaces the previous zero-pad-everything fallback for ragged $K_{\text{eff}}$ inputs. Each event is classified as "safe" or "unsafe" on each attribute by the $K_{\text{eff}, n, a} - r_a \ge 2$ rule (see Overview). Safe-vs-safe pairs flow through the vectorised batched Möbius-method evaluator with within-safe-group zero-padding to a common width; the waste factor $K_{\max} / \overline{K}$ (the ratio of group-maximum $K_{\text{eff}}$ to group-mean $K_{\text{eff}}$, which measures padded slots per useful slot) is minimised by the restriction to the more uniform safe group. Pairs involving any unsafe event flow through `mobius.innerProductDirectAbsSA` (Python `_inner_product_direct_abs_sa`), which enumerates ordered $r$-tuples directly and contracts without a Möbius alternating sum — exact for any $K \ge r$, no cancellation possible. The four submatrices (safe-vs-safe, safe-vs-unsafe, unsafe-vs-safe, unsafe-vs-unsafe) stitch into the full $(N_x, N_y)$ IP matrix without double coverage. The MA dispatcher no longer routes on the presence of NaN entries, since the Möbius-method wrapper handles them natively.

- **K-grouped batched direct enumeration for the unsafe path.** Unsafe-involved pairs are grouped by $(K_{\text{eff}, x}, K_{\text{eff}, y})$ value: each homogeneous sub-block becomes a single vectorised tensor contraction (`np.einsum` in Python; two reduction steps in MATLAB) covering all events with those exact $K_{\text{eff}}$ values, with mathematical coverage `(unsafe_x, all_y) ∪ (safe_x, unsafe_y)`. Uniform-$K_{\text{eff}}$ workloads incur only a few empty-set checks and a single grouped contraction; variable-$K_{\text{eff}}$ workloads dispatch to one contraction per $(K_{\text{eff}, x}, K_{\text{eff}, y})$ subset. See `mobius.maPerAttrInnerMatrix` (MATLAB) / `_ma_per_attr_inner_matrix` (Python) and `tests/test_ma_per_attr_hybrid.{m,py}`.

### Added — Ragged $K_{a, n}$ in `bindEvents`

- **`bindEvents` accepts `K_{a, n} > 1` input.** The output's $n$ attributes each preserve the input $K_{a, n}$. The weight return changed from a rolling-product row to a 1-by-$n$ cell array parallel to `pBound` (numerically equivalent for $K_{a, n} = 1$ via lazy multiplication), so consumers can apply per-attribute weight semantics. Unblocks polyphonic-binding analyses where the input is itself a multi-attribute MAET.

### Added — `translateEvents` / `translate_events`

- **New pre-tensor preprocessing helper.** Translates every value of every attribute belonging to selected groups by a per-group offset. Takes the `pAttr` list one would otherwise feed to `buildExpTens` and returns a transformed `pAttrTranslated` list with the same shape conventions; the output feeds directly into `buildExpTens` without further massaging. Sits alongside `differenceEvents` and `bindEvents` in the cross-event preprocessing family.

- **Sliding-comparison primitive.** Provides the **pre-tensor** route to a sliding comparison along an attribute axis: for each candidate offset $\mu$ on a sweep grid, translate the events and compute a similarity against an un-shifted reference, then read off the peak. Complements the **post-tensor** `windowedSimilarity` route. The two routes coincide in the limit where the post-tensor window has the same shape as the query density, and differ in general by whether locality is set by the query's intrinsic support (pre-tensor) or by an externally chosen window (post-tensor). The pre-tensor route is bounded by the standard cosine and yields symmetric matrices when followed by `cosSimExpTens`; the post-tensor route is magnitude-aware by default and yields asymmetric matrices. Choice between routes is operational, not fundamental.

- **Group-geometry semantics.** Absolute non-periodic groups (`is_per[g] = False`): `value + mu`. Absolute periodic groups (`is_per[g] = True` with `periods[g] > 0`): `(value + mu) mod P`, with the canonical wrap to $[0, P)$ being purely cosmetic — the wrapped periodic Gaussian kernel of `buildExpTens` is invariant under any additive shift by a multiple of $P$, so wrapping or not yields the same MAET. **Relative groups**: structural no-op (a uniform shift cancels in every within-tuple difference); the function emits `translateEvents:noOpRelative` (MATLAB) / `TranslateEventsNoOpWarning` (Python) and leaves the group unchanged. The `is_rel`, `is_per`, and `periods` arguments mirror `buildExpTens` exactly, so the caller can pass the same per-group geometry flags they would pass to the downstream `buildExpTens` call without translation: `periods` is consulted only when `is_per[g] = True`, so a group's natural period (e.g.\\ 12 for pitch class) can be declared even when operating in non-periodic mode for a particular analysis.

- **Multi-slot attributes ($K_{a, n} > 1$) handled without ambiguity.** Every value in the per-event multiset is shifted by the same offset, so unlike post-tensor windowing — where a per-event scalar weight would have to summarise multiple values' distances from a localising centre — translation has no analogous obstruction at $K_{a, n} > 1$. The relative-group no-op and multi-slot uniformity together exhaust the geometry-dependent cases.

- **Multi-group simultaneous translation.** A single call can translate any subset of groups by independent per-group offsets (e.g. pitch by 5 semitones and time by 0.5 beats together). Groups not selected pass through unchanged.

- **API signatures.** Python uses a sparse dict for the per-group offsets:

  ```python
  p_translated = translate_events(
      p_attr, groups, offsets, is_rel, is_per, periods,
  )
  # offsets = {0: 6.0}  -- shift group 0 by 6, leave others alone
  ```

  MATLAB uses a length-$G$ numeric vector with `NaN` as the no-op sentinel:

  ```matlab
  pTranslated = translateEvents(pAttr, groups, offsets, isRel, isPer, periods);
  % offsets = [6, NaN, NaN]  -- shift group 1 (1-indexed) by 6, leave others alone
  ```

  The two are the same operation, expressed in each language's idiomatic sparse-mapping form. The `isRel` / `is_rel`, `isPer` / `is_per`, and `periods` arguments use the same per-group conventions as `buildExpTens`. The MATLAB warning identifier is `translateEvents:noOpRelative`; the Python warning class is `TranslateEventsNoOpWarning` (re-exported as `mpt.TranslateEventsNoOpWarning`).

- **Manuscript context.** Translation is presented in the JMM manuscript's "Sliding comparisons" section as one of two parallel routes (the other being post-tensor windowing) for asking how a similarity profile varies along an attribute axis. The translation primitive is used in §6.1.3 (cadence-progression similarity under transposition) to demonstrate the pre-tensor route, with `windowedSimilarity` used in §6.1.4 for the post-tensor route. The two examples expose the operational differences (bounded vs magnitude-aware, symmetric vs asymmetric, locality coupled to query vs locality independent) in concrete musical settings.

### Fixed

- **`evalExpTens` / `eval_exp_tens`** — Fixed the periodic-relative quadratic form $Q$ to use the pairwise-wrap form (Eq 6 of the preprint), matching `cosSimExpTens` and the JMM Eq. 3.4 integral form to $O((\sigma/P)^{\infty})$. Previously the centres-array path used the algebraic-with-outer-wrap form $Q = \sum_k \mathrm{wrap}(D_k)^2 - (\sum_k \mathrm{wrap}(D_k))^2 / r$ inherited from the v1 implementation — a per-component-image approximation that diverges from the pairwise-wrap form when within-tuple pairwise differences cross $\pm P/2$. The same correctness fix was applied to `cosSimExpTens` in v2.0.1; the parallel fix in `evalExpTens` was overlooked at the time and is now applied. At typical perceptual $\sigma/P \le 0.03$ the two forms agree as $O((\sigma/P)^{\infty})$; above the threshold the difference becomes measurable. Affects all SA centres-fast / centres-full eval sites and the MA per-attribute eval sites in both languages; non-periodic and absolute results are unchanged.

### Changed — `tensorHarmonicity` Möbius-method rewrite

- **`tensorHarmonicity` now bypasses `buildExpTens` entirely.** Routes through `mobius.evalOrbitRel` (the Möbius method's relative-mode evaluator) for the harmonic-template tensor, with per-chord and per-template caching in batched mode (via `containers.Map` in MATLAB / `dict` in Python). No `buildExpTens` density object is constructed, no centres array is materialised. Output is unchanged at the floating-point level. Removes the previous "consider K_template > 3" warning since the Möbius method handles arbitrary K-template without the centres-array memory footprint.

- **Vectorised u-grid loop in `mobius.evalOrbitRel`.** The relative-mode evaluator integrates over the relative-coordinate axis $u$ (the translation parameter for relative-mode densities): a finite "u-grid" of $N_u$ sample points covers the support window, and the Möbius evaluator processes all u-grid points in a single chunked, batched call to `mobius.evalOrbitAbs`. `mobius.evalOrbitAbs` accepts query arrays of shape `(r, ...)` with arbitrary trailing dimensions; the trailing shape is preserved in the output. Per-block intermediate is `O(m_max · N · N_u · n_q_chunk)`, with chunking along the query axis to bound peak memory at a ~1 GB heuristic budget. Verified in `tests/test_orbit_vectorisation.{m,py}`.

- **`tensorHarmonicity` batched mode rewritten to a dedup-and-batch path.** The previous per-row main loop has been replaced by a two-pass implementation: pass 1 computes per-row metadata (`nP`, `dup`, canonical chord key, interval vector) and identifies valid rows; pass 2 groups valid rows by `(nP, dup)`, deduplicates canonical chords within each group, and issues a single batched call to the Möbius relative-mode evaluator per group. Same FP path as scalar mode (so batched values match scalar values to machine precision; previously this held by the result cache, now it holds by construction). For typical uniform-cardinality batches the loop collapses to a single Möbius-method call. The previous warm-up + 10-row calibration estimate has been retired in favour of a row-count gate on the verbose-mode print (silent for fewer than 100 rows, matching the `min_print_sec=10` semantics of the other batched functions). The old `localPackTensorNV` / `_chord_canonical_key` plumbing is no longer needed in the rewrite path; the canonical key is computed directly.

### Changed — Lazy density-struct in `buildExpTens`

- **`buildExpTens` defaults to lazy density construction.** The `lazy` keyword (default `true`) controls whether the expensive density fields (`U_perm`, `wJ`, `V_comb`, `wV_comb`) are materialised at build time. v2.1 and earlier always materialised them; v2.2 builds a "skinny" density struct and defers the expensive fields until a consumer needs them. Most consumers (Möbius-method cosine, eval, entropy) do not need the fields and benefit from the deferral. Consumers that do need the fields (Bulger's method, the centres-array eval) call `ensureExpTensExpensive(dens)` (idempotent) before reading; this is wired internally throughout the toolbox. End-user behaviour is unchanged at the API level. A single existing test that asserted `r=1, isRel=true` errored at build time was relaxed to a warning (id `buildExpTens:isRelDegenerate`) since v2.2's well-defined treatment (constant 0-D space, total mass = $\sum w$, Rényi-2 = 0) makes the configuration valid rather than ill-formed.

### Changed — Console output for batched calls: dispatch announces, cost estimates, and adaptive countdowns

Several user-facing console-output behaviours unified across the five batched-input helpers (`cosSimExpTens`, `templateHarmonicity`, `spectralEntropy`, `virtualPitches`, `entropyExpTens`) so each long-running call emits a consistent, lightly-throttled trace: one dispatch announce per top-level user call, an empirical cost estimate when total runtime is expected to exceed ~10 s, and an adaptive row-count countdown when total runtime is expected to exceed ~5 s. All three pieces are present in both languages with matching semantics; verbose-gating (per-call) and `showHints`-gating (toolbox-wide) are decoupled in both languages. See USER_GUIDE.md §4 "Informational messages" for the user-facing description.

- **Dispatch-announce throttle scope: once-per-session → once per top-level user call.** Each top-level toolbox entry resets the dispatch seen-set on entry. New helpers `matlab/+internal/dispatchScope.m` and `python/mpt/_defaults.py:_dispatch_scope` (the latter a thread-local, depth-counted, re-entrant context manager) implement the scoping. Nested toolbox calls within a single top-level user call share a seen-set, so a batched-raw loop produces one announce per unique dispatch rather than one per item; successive top-level calls each re-announce. Public entry points wrap their bodies via `@_with_dispatch_scope` (Python) or the scope-acquire pattern (MATLAB). The previously session-scoped throttle on dispatch announces is gone; what remains session-scoped is only the one-time `showHints` performance hint (kernel-evaluation hint), which is still cleared only by `reset_defaults` / `mptDefaults('reset')`.

- **Dispatch-announce message format and throttle key: routing reason dropped from both.** Unprobed messages read `cosSimExpTens: chose 'bulger' path.`; probed messages read `cosSimExpTens: chose 'bulger' path (estimated X s); Ctrl+C to cancel.`. The throttle key is `(function, chosen)`, so two different routing reasons leading to the same chosen path within one top-level call collapse to a single announce. Dropping the reason from both the key and the message honours the principle that the visible distinction that matters is which path ran, not why.

- **Adaptive countdown.** Replaces the previous hardcoded "every 100 rows" cadence with an adaptive stride chosen from the empirical calibration. New helpers `matlab/+internal/progressStride.m` and `python/mpt/_utils.py:progress_stride` pick the smallest "nice" stride from `{1, 2, 5, 10, 20, 50, 100, 200, 500, 1000, 2000, 5000, 10000}` such that each print interval takes at least 5 s at the calibrated per-row cost (so 1 ms/row → stride 5000; 1 s/row → stride 5; 10 s/row → stride 1, i.e. print every row). Combined with a `showProgress = (estTotal >= 5)` gate set inside each helper's calibration block, this means: extrapolated total runtime under 5 s → silent regardless of row count; runtime over 5 s → progress at the adaptive stride plus a final flush. No more hardcoded 100-row floor. The per-iteration check is uniform across all five MATLAB and four Python batched helpers: `verbose && showProgress && (mod(k, progStride) == 0 || k == nRows)`. The unit reported is `unique pairs computed` for `cosSimExpTens` and `rows computed` for the others.

- **Demos updated.** `demo_genChainPcs.m`, `demo_gen_chain_pcs.py`, and `demo_edo_approx.py` now pass `verbose=true` to their long-running batched `cosSimExpTens` call so the estimate and countdown surface on the slow sweep, matching the MATLAB `demo_edoApprox.m` counterpart. `demo_triadConsonance.m` / `demo_triad_consonance.py` already used `verbose=true`; `demo_triadSpcsGrid.{m,py}` deliberately stay silent (consistent with their MATLAB counterpart).

- **Demo rename and relabelling: SPCS → PCS where there is no spectral enrichment.** `demo_genChainSpcs.m` is renamed to `demo_genChainPcs.m` (and its Python counterpart `demo_gen_chain_spcs.py` to `demo_gen_chain_pcs.py`), and all "SPCS" and "spectral pitch class similarity" labelling in both these demos and in `demo_edoApprox.m` / `demo_edo_approx.py` is corrected to "PCS" / "pitch class similarity". These demos compute cosine similarity directly on the pitch-class multisets, without `addSpectra` partials applied to either side — that is, **pitch class similarity (PCS)**, not the spectrally enriched form (SPCS). The mislabelling dated back to v2.0.0 when the demos were first added; the implementations were always PCS. (`demo_triadSpcsGrid.{m,py}` remains correctly labelled — it does apply `addSpectra` and so genuinely is SPCS.) USER_GUIDE.md §10 demo-table entries updated accordingly.

- **Associated cleanups.** (1) `entropyExpTens` / `entropy_exp_tens` Rényi-2 path now emits a dispatch announce (it was previously silent in both languages, an unintentional asymmetry with the Shannon path). (2) `tensorHarmonicity` no longer emits a wrapper-level announce; the inner `evalExpTens` does it (the wrapper announce was redundant and named the less informative function). (3) MATLAB test suite (`test_mpt.m`) now silences `showHints` at suite level to match Python's `python/tests/conftest.py` autouse fixture; tests that explicitly verify announce content (`test_dispatcher_ip_probe.m`, `test_tensor_harmonicity_orbit.m`, `test_harmony.m`) opt back in via local `mptDefaults('showHints', true)` save/restore. (4) Stale "once per session" references in `cosSimExpTens.m`, `evalExpTens.m`, `mptDefaults.m`, and `python/mpt/_defaults.py` updated to "once per top-level user call". (5) Python dispatch tests (`test_dispatcher_ip_probe.py`, `test_dispatcher_probe.py`) updated for the new format and split the previous throttle test into within-call and across-call cases reflecting the new contract.

### Changed — `windowedSimilarity` argument order (breaking)

- **Positional argument order: `(densContext, densQuery, windowSpec, offsets, ...)`.** The first positional argument is the operand the window multiplies (the operand whose region is selected by each sweep position); the second is the unwindowed comparison template. This reflects the asymmetric roles: the context is what slides under the window; the query is the reference shape whose self inner product appears in the denominator under both normalisation modes. v2.1 took `(densQuery, densContext, ...)`; existing call sites must swap their first two positional arguments. The list-mode cartesian output shape follows the same convention: `(n_c, n_q, M)`, versus `(n_q, n_c, M)` in v2.1.

### Added — `normalize` NV on `cosSimExpTens` and `windowedSimilarity`

- **`normalize` / `normalise` keyword on both functions.** Two values, `'cosine'` and `'oneSidedDenom'`, case-insensitive on the value; both spellings of the keyword name are accepted. On `cosSimExpTens` / `cos_sim_exp_tens` the default is `'cosine'` — the strict shape-only cosine similarity $\langle X, Y \rangle / \sqrt{\langle X, X \rangle \langle Y, Y \rangle}$, bounded in $[-1, 1]$ and invariant to positive scalars on either operand. On `windowedSimilarity` / `windowed_similarity` the default is `'oneSidedDenom'` — the magnitude-aware $\langle h \cdot f_C, f_Q\rangle / \langle f_Q, f_Q\rangle$ (divide only by the query's unwindowed self inner product), giving self-similarity at full window coverage equal to 1 and an unbounded range above. The alternative on either function reaches across: `cosSimExpTens(..., 'normalize', 'oneSidedDenom')` divides by the second operand's self inner product alone (a magnitude-aware reading sensitive to scalar rescalings of the first operand), and `windowedSimilarity(..., 'normalize', 'cosine')` gives the strict shape-only cosine for the windowed comparison. The strict shape-only cosine on `windowedSimilarity` is closed-form only when the pointwise square $h^2$ of the window remains in the toolbox's `(size, mix)` family: pure Gaussian (`mix = 0`, with $h^2$ Gaussian and width scaled by $1/\sqrt 2$) and pure boxcar (`mix = 1`, with $h^2 = h$). Intermediate `mix` raises with a clean message directing the user to `'oneSidedDenom'` or to set the mix to 0 or 1. See User Guide §3.1 "Normalisation: one-sided versus strict shape-only".

### Changed — `windowedSimilarity` is the sole user-facing entry point for windowed similarity

- **`cosSimExpTens` / `cos_sim_exp_tens` no longer accept `WindowedMaetDensity` operands.** In v2.1, passing a `WindowedMaetDensity` as one operand silently dispatched to the closed-form windowed inner product, returning a magnitude-aware similarity (using the unwindowed L2 norms of both operands as the divisor) rather than a strict cosine similarity in $[0, 1]$. The function name `cosSimExpTens` promises the latter, so the dispatch was a semantic crack: a user calling `cosSimExpTens(densQ, wmd)` got an operation with substantially different mathematical content and value range than `cosSimExpTens(densQ, densC)`. v2.2 raises a clear error in both languages (`cosSimExpTens:windowedNotSupported` in MATLAB, `TypeError` in Python) directing users to `windowedSimilarity`, which is now the sole user-facing entry point for the windowed similarity in both the single-offset and multi-offset cases. The list-mode dispatcher rejects `WindowedMaetDensity` entries at the same point.

- **`windowedSimilarity` now emits the standard console-output pattern.** Once per top-level user call: a dispatch announce `windowedSimilarity: chose 'direct' path.` (the closed-form windowed inner product is the `direct` method — a single closed-form expression evaluated as written, with no clever decomposition such as Bulger's inclusion–exclusion or the orbit-collapsed Möbius reformulation). When the sweep is expected to take at least 10 s, a cost-estimate line `windowedSimilarity (batched, M rows): estimated time ~X s (Ctrl+C to cancel).` derived from the standard warm-up + 5-sample empirical calibration. When the sweep is expected to take at least 5 s, an adaptive countdown at the cadence picked by `internal.progressStride` / `_utils.progress_stride`, plus a final flush `windowedSimilarity: done.`. All five pieces (announce, warm-up, estimate, countdown, done flush) are gated on `verbose=true` and `showHints=true` in the same way as the other batched helpers.

### Performance

These entries cover inner-loop refinements to the kernel-evaluation paths in addition to the analytical-method gains documented above under *Added — Möbius method*.

- **`cosSimExpTens` periodic-relative IP kernel: redundant component-wise outer wrap eliminated.** In the periodic-relative case the IP kernel previously applied an outer per-component wrap of the difference tensor before computing the pairwise-wrap quadratic form $Q$. Pairwise wrapping subsumes outer wrapping when both `isRel` and `isPer` are true, so the outer wrap is redundant work. Removing it gives roughly 1.5–2× speedup on the cos-sim rel+per path in both languages. Applies symmetrically to the MAET log-kernel accumulator (`_ma_log_kernel` in Python; the corresponding helpers in `cosSimExpTens.m`), the chunked and full SA IP cores in `cosine.py`, and the windowed-IP path (`+internal/windowedInnerProduct.m` and its Python counterpart).

- **`templateHarmonicity` / `template_harmonicity` cross-correlation: `np.convolve` → `scipy.signal.correlate` (Python).** The chord-template cross-correlation at the heart of `templateHarmonicity` switches from `np.convolve(chord, tmpl[::-1])` to `scipy.signal.correlate(chord, tmpl, method='auto')`. Same numerical output; ~6× faster for the relevant template/chord sizes via SciPy's FFT-based correlation path at `method='auto'`'s crossover.

- **`windowedSimilarity` per-density self-IP denominators hoisted out of the offset sweep.** The constant-across-offsets self-inner-product factors $\langle T_a, T_a \rangle$ and $\langle T_b, T_b \rangle$ in the windowed-similarity normaliser were being recomputed inside the per-offset loop. They are now computed once per pair and reused across all offsets, via a new `_cached_norms` kwarg on the Python helper and corresponding norm-only-mode signature on the MATLAB helper. Speedups of ~2.6× on `demo_maetWindowing` and ~1.6× on `demo_windowingReference`.

- **`evalExpTens` / `eval_exp_tens` periodic-relative kernel inner loop.** The pairwise-wrap loop introduced by the Eq 6 correctness fix (see *Fixed* above) uses vectorised slot-0 wraps and an in-place inner pair loop with preallocated workspaces in Python (`np.subtract / np.divide / np.floor / np.multiply / np.add` with `out=` parameters). The hybrid pattern bounds the worst-case end-to-end slowdown vs the prior (incorrect) algebraic form at ~2× rather than the ~4× a naïve pairwise-wrap implementation would impose. MATLAB sites use the same hybrid pattern (slot-0 wraps vectorised, inner pairs looped). Applies to all SA and MA centres-path eval sites in both languages.

### Internal

- **`ensureExpTensExpensive` moved to `matlab/+internal/`.** The lazy-density materialiser is a toolbox-internal helper called only by consumer entry points (`cosSimExpTens`, `evalExpTens`, `windowedSimilarity`) on density inputs, and was the one top-level MATLAB function not part of the documented user-facing surface. Relocated to `matlab/+internal/ensureExpTensExpensive.m` to follow standard MATLAB +package conventions for non-user-facing helpers and to match the placement pattern of the other internal utilities (`gaussianKernelSum`, `chordCacheKey`, `dispatchScope`, etc.). Callers updated to `internal.ensureExpTensExpensive(...)`. No API or behaviour change for users; the function was never documented as user-callable. Python has the analogous `_ensure_exp_tens_expensive` already module-private (underscore prefix), so no Python-side change.

- **Closed-form windowed inner product extracted to an internal helper.** In v2.1 the closed-form windowed inner product was implemented inline inside `cosSimExpTens.m` / `cos_sim_exp_tens`; v2.2 moves it to `matlab/+internal/windowedInnerProduct.m` and `python/mpt/tensor._windowed_inner_product`, called from `windowedSimilarity`'s sweep loop. Not a public entry point — single windowed similarities at a chosen centre are obtained through `windowedSimilarity` with a single-column `offsets` (default `reference` is the query's centroid; pass `'reference'` / `reference=` explicitly to measure from an alternative origin).

- **Cross-language equivalence tests.** Hardcoded golden values pin down numerical agreement between the MATLAB and Python implementations to $10^{-8}$ relative across the v2.2 surface (Möbius-method cosine SA + MA including the safe/unsafe hybrid, Rényi-2 entropy SA + MA, Möbius-method `tensorHarmonicity`, and Möbius-method `evalExpTens`). See `tests/test_cross_language_golden.{m,py}`.

- **Cross-language speed parity for the Möbius method.** Targeted spot-checks at $(r, K) \in \{(2, 8), (3, 8), (3, 12), (4, 8), (5, 6)\}$ time the MATLAB Möbius-method IP/eval evaluators against their Python NumPy-einsum equivalents at matched inputs. The contraction graph is precomputed once per orbit at table-build time (see "Orbit-table contraction-graph precomputation" below) and consumed at runtime by `mobius.executeRecipe` (MATLAB) or `np.einsum(..., optimize=path)` (Python), avoiding per-call dispatch overhead in the contraction step. MATLAB / Python ratios are median 0.53× across the spot-check range (range 0.32×–1.37×, MATLAB generally the faster of the two at the median). The Möbius and Bulger methods remain mathematically equivalent at default settings; users do not need to choose between them. See `tests/bench_orbit_xlang.{m,py}` for the bench harness; `+mobius/buildContractRecipe.m` and `+mobius/executeRecipe.m` (MATLAB) and `_mobius._compute_einsum_path_*` (Python) for the implementations.

- **Orbit-table contraction-graph precomputation.** Each orbit table entry carries precomputed contraction-graph information embedded at build time:
  - **MATLAB** orbit structs carry three recipe fields (`recipeIP`, `recipeGrid`, `recipeBatched`) corresponding to the three IP-consumer call patterns (`mobius.innerProductOrbit`, `mobius.innerProductOrbitGrid`, `mobius.innerProductOrbitPwBatched`). Each recipe is a struct array of merge steps with precomputed `lhsPerm` / `rhsPerm` / dim-class counts. Runtime calls `mobius.executeRecipe`, which executes the recipe directly without invoking `intersect`, `setdiff`, `unique`, or `ismember`.
  - **Python** orbit entries carry three precomputed `np.einsum_path` outputs (`einsum_path`, `einsum_path_grid`, `einsum_path_pw_batched`) and one pre-built einsum string (`einsum_str_pw_batched`). Runtime calls `np.einsum(..., optimize=path)`, skipping NumPy's per-call path optimisation.

  Table loaders (`mobius.getOrbitTable` in MATLAB, `_mobius._ensure_paths` in Python) augment in-memory entries with these fields if absent from the loaded file, ensuring forward-compatibility with patch-version table additions.

- **`windowedSimilarity` propagates `truncation_sigmas` and `kernel_precision` deeply.** The kwargs are accepted at the `windowedSimilarity` boundary and threaded explicitly through the call chain: `_windowed_similarity_pair` (Python) and the corresponding MATLAB local function carry the kwargs, the inner cosine-similarity computation forwards them on every call, and recursive `windowedSimilarity` invocations propagate them onwards. Explicit threading is robust under recursion and thread-safe.

- **Dispatcher routing — analytical pre-screen + warmup probe.** When the analytical cost model doesn't clearly favour one path, the eval and inner-product dispatchers fall back to a wallclock probe that times each candidate path on a small subset of the workload. Each path runs a warmup pass (discarded) before its timed pass, so the measurement is from a fully-cache-warmed steady state and is independent of whichever path most recently executed on the full workload. The analytical pre-screen fires when one path's analytical cost is at least 3× smaller than the other (constants `PRESCREEN_CENTRES_DOMINANCE`, `PRESCREEN_ORBIT_DOMINANCE`, `PRESCREEN_IP_DOMINANCE` in both languages), skipping the probe entirely in the clear-winner case. With this design, identical workloads receive identical routing decisions on every call.

- **Vectorised multi-dimensional truncated kernel-sum path.** `localTruncatedKernelSum` in `matlab/+internal/gaussianKernelSum.m` processes (query, neighbour-bucket) pairs in vector form: for each chunk of queries it expands all $3^{\text{dim}}$ neighbour buckets in one matrix operation, masks out-of-bounds neighbours and empty buckets via vectorised comparisons, expands each (query, run-bucket) pair into per-centre pairs via cumsum-based ragged indexing, and accumulates kernel sums via `accumarray`. Memory budgeting matches the exact path's heuristic (per-chunk peak $\sim (\text{dim} + 1) \cdot n_J \cdot \text{chunkSize}$ scalars, capped at 50% of `MaxPossibleArrayBytes` or a 4 GB fallback). Applies whenever `truncationSigmas` is finite and the workload is multi-dimensional; the 1-D path is separately vectorised along sorted centres.

- **`kernelChunkBytes` / `kernel_chunk_bytes` toolbox default.** All kernel-matrix workloads (centres-path and IP-path evaluators in both languages, plus the Möbius relative-mode evaluator) share a single per-chunk byte budget configurable via this default. The factory value `'auto'` resolves at call time to half of currently available physical memory (Linux `/proc/meminfo` `MemAvailable`; macOS `vm_stat` `free + inactive + speculative`; Windows `memory().PhysicalMemory.Available` in MATLAB and `GlobalMemoryStatusEx` via `ctypes` in Python). A 4 GiB fallback applies if all platform queries fail. Explicit positive-integer byte values override globally via `mptDefaults('kernelChunkBytes', N)` (MATLAB) or `mpt.set_default(kernel_chunk_bytes=N)` (Python). Per-query allocation estimates account for the broadcast difference tensor, its square, and the summed-then-exponentiated intermediate being briefly co-resident (`(2 \cdot \text{dim} + 2) \cdot n_J \cdot \text{bytesPerScalar}` for the broadcast-pattern sites; site-specific formulas for the IP-side and Möbius-relative paths). Resolution happens on every chunker call, so the budget tracks memory pressure across a session. The platform queries are factored into `internal.availableMemory` (MATLAB) and `mpt._utils.available_memory_bytes` (Python); resolution into `internal.kernelChunkBytesResolved` and `mpt._utils.kernel_chunk_bytes_resolved`.

- **Cost-model tables extended to $r = 7, 8$.** Python's `_ORBIT_ABS_PER_ATTR_MS`, `_ORBIT_RELPER_PER_PAIR_K2_MS`, and `_ORBIT_RELNONPER_PER_PAIR_K2_MS` lookup tables (consulted by `_select_ma_inner_product_method`) gain entries for $r = 7, 8$ extrapolated from the empirical 3× orbit-count growth per $r$ anchored to measured $r = 2..6$ values. These are conservative and may be re-calibrated against measurement once the new shipped tables are in widespread use.

- **Packaging.** The Python package now ships the pre-built orbit pickles via `[tool.setuptools.package-data]` in `pyproject.toml` (`mpt = ["_orbit_tables/*.pkl"]`); without this, the sdist/wheel build silently omits non-`.py` files and a fresh `pip install` would fall through to a multi-minute on-demand build on first `get_orbit_table()` call. The `mpt.__version__` constant was bumped from a stale `"2.0.0"` (never updated at the v2.1 release) to `"2.2.0"`, matching the `pyproject.toml` declared version.

## [2.1.0] — 2026-05-08

### Overview

Version 2.1.0 generalises the expectation tensor framework to **multiple attributes per event** (multi-attribute expectation tensors, MAETs), and adds a **post-tensor windowing** mechanism for sliding-window template matching along any MAET group. Together these let the toolbox handle questions that the single-attribute treatment of v2.0.0 could not: locating motif recurrences over time, probe-tone scanning on irregularly timed contexts, polyphonic voice-aware analyses, and multi-quantity similarity (e.g., pitch combined with register, timbre, or metrical position) with the same closed-form analytical cosine-similarity inner product that underlies the single-attribute case.

Two cross-event preprocessing primitives, `differenceEvents` and `bindEvents`, support analyses based on inter-event differences and on n-tuples of consecutive events. Two utilities for sequential analysis, `continuity` and `seqWeights`, also accompany the main additions. A categorical-encoding utility, `simplexVertices`, supplies equidistant vertex coordinates for simplex-coded categorical attributes (voice, instrument, etc.) suitable for MAET inputs.

This release also adds **soft (`sigma > 0`) support to the structural measures `sameness` and `coherence`** — both gain an optional positive `sigma` argument that softens the discrete equality / ordering tests against Gaussian positional uncertainty — and **a `sigmaSpace` flag, shared across `sameness`, `coherence`, and `nTupleEntropy`** (whose `sigma` argument already existed in v2.0), controlling whether `sigma` is interpreted as positional uncertainty on each event (the new default, propagated through index sharing among derived intervals) or as independent uncertainty on each derived interval (matching the v2.0 numerical behaviour of `nTupleEntropy` at `sigma > 0`). A separate strand adds **Monte Carlo sigma support to the Argand-DFT family** via the new `dftCircularSimulate` function: `balanceCircular`, `evennessCircular`, and `projCentroid` accept an optional `sigma` argument, with closed-form analytical damping where the geometry permits it (`projCentroid`, since the projection is linear in $F(0)$) and Monte Carlo where it does not (`balanceCircular`, `evennessCircular`).

A third major strand is the **unification of dispatch and addition of consumer-level batching**. The Python entry points `eval_exp_tens`, `cos_sim_exp_tens`, and `entropy_exp_tens` are now polymorphic: each accepts a single density object, a list of densities, or raw arrays for either single-multiset or batched-multiset evaluation. The MATLAB equivalents are likewise extended where each language idiomatically permits. The harmony, entropy, and consonance wrappers (`tensorHarmonicity`, `templateHarmonicity`, `virtualPitches`, `spectralEntropy`) accept 2-D pitch matrices for batched evaluation. The DFT-equivariant family (`dftCircular`, `meanOffset`, `edges`, `projCentroid`, `circApm`), the structural-measure family (`coherence`, `sameness`, `nTupleEntropy`), and the Monte Carlo functions (`balanceCircular`, `evennessCircular`) all gain batched-input dispatch. Every batched path uses canonical-form deduplication to collapse symmetry-equivalent rows onto a single cached computation. The previous standalone entry points `cos_sim_exp_tens_raw`, `eval_exp_tens_raw`, `batch_cos_sim_exp_tens`, and `batchCosSimExpTens` are now deprecated shims forwarding to the unified entry points.

The release is additive: existing v2.0.0 single-attribute calling conventions for `buildExpTens`, `evalExpTens`, `cosSimExpTens`, and `entropyExpTens` are preserved unchanged. The new multi-attribute calling form is dispatched on input shape (a cell / list of per-attribute arrays for `p`) and is otherwise separate. The structural and Argand-DFT extensions are likewise additive at `sigma = 0`; a small documented numerical change to `nTupleEntropy` at `sigma > 0` is described in [MIGRATION.md](MIGRATION.md) and below.

### Added — Multi-attribute expectation tensors

- **MAET calling form for `buildExpTens`, `evalExpTens`, `cosSimExpTens`, `entropyExpTens`.** Each now accepts a multi-attribute density specification alongside the v2.0.0 single-attribute form. A MAET carries $A$ attributes in $G \le A$ groups; each attribute has its own tuple order $r_a$ and per-event slot count $K_a$, and each group has shared $\sigma$, `isRel`, `isPer`, and `period`. The density factorises as a product of per-attribute Gaussian-mixture kernels, and the cosine-similarity inner product factorises analytically in the same way. The single-attribute case is the special case $A = 1$. See User Guide §3.1 for the mathematical formulation and the post-tensor windowing mechanism built on top of it.

### Added — Cross-event preprocessing

- **`differenceEvents`.** Preprocessing helper that replaces each selected group's event sequence with inter-event differences before tensor construction. Per-group differencing order $k$ produces the $k$-th finite differences along the event axis (reducing the event count by $k$); periods supplied per group wrap each raw difference to the shortest signed arc. Weights propagate as rolling products of width $k + 1$, interpretable as the probability that all constituents of a difference are jointly perceived. Inputs are restricted to $K_a = 1$ slots per event; see User Guide §3.1 (Cross-event preprocessing) for the rationale and the voices-as-attributes pipeline for polyphonic step-size analyses. Output feeds directly into `buildExpTens`. This supports analyses over interval content, IOIs, and higher-order differences without needing a dedicated interval representation.

- **`bindEvents`.** Preprocessing helper that gathers $n$ consecutive events into a single super-event with $n$ separate attributes carrying the values at lags $0$ through $n-1$. Output is a length-$n$ list of $K_a \times N'$ matrices, suitable as the `pAttr` argument of `buildExpTens` with all $n$ attributes assigned to a single group sharing $\sigma$ and the other group-level parameters. Lag slots are kept as separate attributes (rather than a single $K_a = n$ multi-slot attribute) because lag identity is non-exchangeable — within-attribute multiset symmetry would otherwise collapse ordered tuples to unordered ones. Per-event weights propagate per-attribute (each output attribute inherits the slot weights of the underlying event at its lag); `buildExpTens` multiplies across attributes during tuple enumeration, so the end-to-end effective weight of a bound super-event equals the product of the $n$ constituent events' weights, matching the differencing rule. Inputs may have any $K_a \ge 1$: when the input attribute has multi-value slots, each output attribute carries the full $K_a$-slot vector of its underlying event, with within-attribute exchangeability preserved per output attribute. Default output has $N - n + 1$ super-events; a `circular` option produces $N$ by wrapping around the input sequence. Composes with `differenceEvents`: the standard pipeline `differenceEvents` $\to$ `bindEvents` $\to$ `buildExpTens` $\to$ `entropyExpTens` recovers the n-tuple entropy of Milne & Dean (2016) at $\sigma \to 0$ and uniform weights, and extends it to the smoothed continuous case, weighted events, and non-periodic domains; for $n \ge 2$ the bound MAET is itself an $n$-dimensional density supporting cosine-similarity comparison of n-tuple distributions across pieces and the rest of the MAET pipeline. Used without preceding differencing, produces n-grams in absolute pitch or time register, useful when register or absolute timing carries musical information that the differenced view discards.

### Added — Post-tensor windowing

- **`windowTensor`.** Wraps a MAET with a per-group window specification (widths, shapes, and centres), returning a `WindowedMaetDensity` that is consumed lazily by `evalExpTens` (pointwise multiplication by the window) and by `cosSimExpTens` (closed-form windowed inner product). Windows are specified in a one-parameter family by `size` (width, in multiples of group $\sigma$) and `mix` in $[0, 1]$ (shape: pure Gaussian at 0, pure rectangular at 1, rectangular-convolved-with-Gaussian in between). A numeric size-1 input to `window_spec['centre']` (Python: a Python scalar, 0-D ndarray, or numeric ndarray of size 1; MATLAB: a numeric scalar or 1×1 numeric array) is broadcast to fill every per-attribute slot uniformly; convenient when one window centre value is wanted everywhere. List/cell inputs are always interpreted structurally and never broadcast.

- **`windowedSimilarity`.** Sweeps a series of window centres across a windowed context and returns the windowed-similarity profile against a query. Implements cross-correlation: at each sweep centre $c$ in a windowed group, the query is translated so that its effective-space mean within that group moves onto $c$, so a peak at $c$ means the query pattern is present in the context near $c$. The normaliser is one-sided by the query's unwindowed $L^2$ self inner product, $s = \langle h \cdot f_X, f_Y \rangle / \langle f_Y, f_Y \rangle$, making the returned profile magnitude-aware (denser matching content gives a higher value than sparser content). The output is *not* a cosine similarity in the strict sense (the unwindowed denominator means it is not bounded in $[-1, 1]$ across sweep positions); "cosine similarity" is reserved for the strict shape-only form, which is not currently implemented in the toolbox. See User Guide §3.1 "Post-tensor windowing".

- **Polymorphic query and context.** Either or both of `densQuery` and `densContext` may be a cell array (MATLAB) or list (Python) of MaetDensity structs, in which case the function returns a cell array (MATLAB) or list (Python) of profiles. A new `'mode'` name-value option controls the pairing: `'pairwise'` (require equal lengths; pair element-by-element; returns a 1-by-n cell), `'cartesian'` (cross every query with every context; returns an n_q-by-n_c cell), or `'auto'` (default; pairwise when lengths match, cartesian otherwise). Option II shape rule: a length-1 list returns a length-1 cell. Scalar inputs continue to dispatch to the existing single-pair path with byte-identical results. The `'reference'` option also gains a per-query form: a length-n_q cell-of-cells (each entry itself a 1-by-A cell of per-attribute reference vectors), disambiguated from the shared length-A form by element type.

- **`reference` option.** A `reference` keyword argument (Python) / name-value pair (MATLAB) that allows the offset-axis origin per attribute to be set explicitly. When absent or `None` / `[]` (default), the prior unweighted-centroid behaviour is preserved byte-for-byte. When supplied, the call uses the given reference as the offset-axis origin per attribute — for example, calibrated to a canonical harmonic query so that offsets retain a stable musical-interval reading across queries with different slot counts, slot values, or slot weights. See User Guide §3.1 "Post-tensor windowing" for the practical guidance on default versus fixed-reference choices and the `demo_windowingReference` / `demo_windowing_reference` demo for a worked walkthrough.

- **Wrapped-Gaussian image summation for periodic groups.** For periodic groups, `windowedSimilarity` / `windowed_similarity` and the windowed branch of `evalExpTens` / `eval_exp_tens` use the wrapped Gaussian window (or the wrapped rectangular-convolved-with-Gaussian for `mix > 0`): the sum of line-case window functions at all periodic images of the centre, $h_{\text{per}}(x) = \sum_{n \in \mathbb{Z}} h_{\text{line}}(x - nP)$. The windowed inner product inherits this linearity and is computed as a sum of line-case inner products evaluated at shifted centres, truncated adaptively when the latest image-pair's contribution falls below $10^{-12}$ of the running maximum (or $10^{-7}$ for `kernel_precision = 'single'`) — the result equals the exact wrapped-window inner product to floating-point precision across all regimes of $\lambda\sigma / P$. For 1-D groups and multi-D absolute groups, the per-pair factor factorises across axes and the image sum factorises into per-axis sums (cost linear in dimension); for multi-D relative groups the line-case formula is used directly (image summation for the non-factorising kernel is a future extension). See User Guide §3.1 "Post-tensor windowing".

- **Analytical closed form.** The cosine-similarity inner product between a windowed MAET and an unwindowed MAET is closed-form analytical across the full `(size, mix)` family for all 1-D groups and all multi-dimensional absolute groups; for multi-dimensional relative groups, it is established for the pure-Gaussian window only, with approximate handling of the full family left as a future extension.

### Added — Sequential-analysis utilities

- **`continuity`.** Expected length and signed magnitude of the backward same-direction run leading up to each query, under Gaussian pitch uncertainty. Smoothed directional-agreement score $a_k = \mathrm{erf}(i_k/(2\sigma)) \cdot \mathrm{erf}(i_N/(2\sigma))$ drives a backward walk from the most recent context interval. Two break-threshold modes (`'strict'` with $\theta = 0$, `'lenient'` with $\theta = -1$) and an explicit-threshold override. Returns `(count, magnitude)`; `magnitude / count` is a trend-slope measure. An optional `w` argument supplies per-event salience weights; the salience of difference event $k$ is the rolling product $w_k \cdot w_{k+1}$, matching `differenceEvents` at order 1, and scales each interval's contribution to `count` and `magnitude`. Internally, the function routes through `differenceEvents` to compute both the context intervals and their weights, so the preprocessing is shared with the MAET-with-differencing pipeline; the read-out (a directional, order-preserving backward walk with a break condition) is not. Defined only on linearly ordered domains.

- **`seqWeights`.** Constructs length-$N$ position-weight vectors from a named specification (`'flat'`, `'primacy'`, `'recency'`, `'exponentialFromStart'`, `'exponentialFromEnd'`, `'uShape'`, `'uAsym'`) or an explicit profile. A *U-shape* profile is one with high weight at both the start and end of the sequence and lower weight in the middle, modelling the combined primacy and recency effects in serial memory (recent items remembered well, oldest items remembered well, items in the middle remembered worst). Supports time-based decay via an optional time index. Combines an intrinsic per-event salience with a memory-decay or attentional profile in a single inspectable vector, usable anywhere a weight argument is accepted. The `'uAsym'` profile is a three-parameter U-shape with separate decay rates for the primacy and recency components: `alpha * exp(-decayRateStart * t) + (1 - alpha) * exp(-decayRateEnd * (t_end - t))`; reduces to `'uShape'` when `decayRateStart == decayRateEnd`. In addition to a named string and an explicit length-$N$ vector, `spec` may be a function (Python callable, MATLAB function handle) of the time vector that returns a length-$N$ profile, allowing arbitrary user-defined profiles (hyperbolic decay, custom mixtures, etc.) to be applied with the same length validation and `w` multiplication as built-in specs.

### Added — Categorical-encoding utility

- **`simplexVertices`** (MATLAB), **`simplex_vertices`** (Python). Returns the $N$ vertices of a regular $(N-1)$-simplex centred at the origin in $\mathbb{R}^{N-1}$, with all pairwise vertex distances equal to a specified `edgeLength` (default 1). Supports the simplex-coded encoding of an $N$-level categorical attribute (voice identity, instrument, etc.) for MAET inputs: each level is represented by an $(N-1)$-dimensional coordinate row, fed as values for the $N-1$ numerical sub-attributes of a single categorical group. All levels are pairwise equidistant, so no level is privileged over any other — in contrast to dummy or treatment coding. Construction uses the centred standard basis of $\mathbb{R}^N$ projected onto an orthonormal basis of $\mathbf{1}^\perp$; the result is rotation-equivalent across choices of basis, which is irrelevant for downstream MAET computations.

### Added — Data structures

- **`MaetDensity`** and **`WindowedMaetDensity`.** Tagged dataclasses (Python) / tagged structs (MATLAB) produced by `buildExpTens` (multi-attribute form) and `windowTensor` respectively. `evalExpTens`, `cosSimExpTens`, and `entropyExpTens` dispatch on the tag.

### Added — Soft (`sigma > 0`) structural measures

- **`sameness` / `coherence` — `sigma` argument with `sigmaSpace` flag.** Both functions now accept an optional positive `sigma` that softens the discrete equality / ordering tests against Gaussian positional uncertainty. With `sigma = 0` (default) the v2.0 hard counts are recovered byte-for-byte. With `sigma > 0`, `sameness` replaces each `[d1 = d2]` indicator with a Gaussian match kernel $\exp(-(d_2 - d_1)^2 / (2V))$, and `coherence` replaces each `[d2 \le d1]` indicator with the Gaussian-CDF probability $\Phi((d_1 - d_2)/\sqrt{V})$. The variance $V$ depends on the new `sigmaSpace` name-value flag: with `sigmaSpace = 'position'` (default), $V$ is computed per pair of intervals from the sharing structure of their endpoints (so the diatonic tritone, where the fourth and fifth share both endpoints with reinforcing signs, has $V = 8\sigma^2$ and the ordering test sees a tie at every $\sigma > 0$); with `sigmaSpace = 'interval'`, $V = 2\sigma^2$ uniformly (intervals treated as independent draws, ignoring index correlations). Float positions and float `period` are accepted when `sigma > 0`. See User Guide §3.5 (Soft sigma semantics) and §6.5.

- **`nTupleEntropy` — `sigmaSpace` flag.** Adds a `sigmaSpace` name-value pair with the same semantics as `sameness` and `coherence`, governing whether the supplied `sigma` is treated as positional uncertainty on each event (the new default, with derived steps inheriting variance $2\sigma^2$ per slot via the marginal-matched approximation) or as independent uncertainty on each derived step (matching v2.0 numerical behaviour). At $n = 1$ the two flags are exactly related: `'position'` with $\sigma$ produces identical entropy to `'interval'` with $\sigma\sqrt{2}$. At $n \ge 2$ with `sigmaSpace = 'position'`, the current implementation uses the marginal-matched approximation (slots independent at $\sigma_{\text{eff}} = \sigma\sqrt{2}$); a one-time `UserWarning` (Python warning class `UserWarning` with message containing `marginal-matched`; MATLAB warning identifier `nTupleEntropy:positionApprox`) flags this. Full position-aware $n \ge 2$ support, requiring a non-diagonal Gaussian-mixture entropy routine, is planned for a future release. See User Guide §3.5 and §6.5.

- **`positionVariance`.** Shared helper that computes the variance of a signed sum of independently jittered positions, $V = \sigma^2 \sum_a (\sum \text{signs at index } a)^2$. Used internally by the position-aware paths of `sameness` and `coherence`; documented and exported because users implementing their own position-aware structural measures may want to call it directly. The same logic is exposed in Python as `mpt._utils.position_variance`.

### Added — Argand-DFT Monte Carlo

- **`dftCircularSimulate` / `dft_circular_simulate`.** Monte Carlo estimator of the distribution of Argand-DFT coefficient magnitudes under independent Gaussian positional jitter $\widetilde{p}_k = (p_k + \eta_k) \bmod P$, $\eta_k \sim \mathcal{N}(0, \sigma^2)$, where $P$ is the period. For each draw, the perturbed positions are sorted (capturing the perceptual reordering when noise is comparable to the smallest event-to-event gap), the Argand vector is formed, and the DFT is computed. Returns the per-coefficient mean and standard deviation of $|\widetilde{F}(k)|$ across draws by default; a third optional output (`samples` / `return_samples=True`) yields the full $n_{\text{draws}} \times K$ magnitude matrix for histogram or quantile analysis. Name-value parameters `nDraws` (default 10000) and `rngSeed` for reproducibility.

- **`balanceCircular`, `evennessCircular` — `sigma` argument.** Both functions now accept an optional positive `sigma` that triggers Monte Carlo estimation via `dftCircularSimulate` and returns the *expected* balance / evenness under positional jitter. At `sigma = 0` the v2.0 deterministic value is recovered exactly. The MATLAB versions also return the per-coefficient standard deviation as an optional second left-hand-side output (idiomatic `nargout`-driven multi-return); the Python versions accept a `return_std=True` flag that switches the return type from scalar to `(mean, std)` tuple. Backward-compatible at `sigma = 0` (scalar return preserved). Name-value `nDraws` and `rngSeed` are forwarded to the simulator. The augmented triad — perfectly balanced at `sigma = 0` — exhibits the expected Rayleigh-bias positive shift of $E[|F(0)|]$ at `sigma > 0`. See User Guide §6.4.

- **`projCentroid` — `sigma` argument (analytical closed form).** Because $y(x) = \mathrm{Re}(F(0) \cdot e^{-2\pi i x / P})$ is linear in $F(0)$ and $F(0)$ is permutation-invariant under positional jitter, no Monte Carlo is needed for the mean projection: $E[y(x)] = \alpha_1 \cdot y_{\text{deterministic}}(x)$ where $\alpha_1 = \exp(-2\pi^2 \sigma^2 / P^2)$ is the standard kernel-smoothing damping factor. Phase is preserved exactly in expectation, so `centPhase` is unchanged; `centMag` returns $\alpha_1 \cdot |F(0)| = |E[\widetilde{F}(0)]|$, the magnitude of the *complex mean centroid* — consistent with the projection. The distinct scalar $E[|\widetilde{F}(0)|]$ — the *mean centroid magnitude under jitter*, which picks up positive Rayleigh-style bias — is what `balanceCircular(p, w, period, sigma)` returns; the two answer different balance-related questions (see User Guide §3.5 "Two scalars, two balance-related questions").

### Added — Unified dispatch and consumer-level batching

A coherent strand of changes makes the consumer-facing entry points polymorphic on input shape and adds 2-D-pitch-matrix batching to most function families. The convention throughout: each row of a 2-D pitch matrix is one multiset, the $M$ rows form the batch, columns are slots, and NaN-padding allows variable-cardinality batches; weight matrices match the pitch-matrix shape. Every batched path uses canonical-form deduplication — symmetry-equivalent rows (permutation of slots, transposition modulo the period in `isRel = true` modes, period-equivalence in `isPer = true` modes) are computed once per equivalence class and the result is mapped back to all matching rows. Which symmetries are exploited depends on what each function's output is actually invariant to (transposition-equivariant measures collapse only permutation and period-equivalence; transposition-invariant measures collapse all three). Name-value arguments such as `'spectrum'`, `'precision'`, and `'dedup'` are uniformly available across raw scalar and raw batched modes where they are meaningful. See User Guide §4 ("Consumer-level batching" and "Canonical-form deduplication") for the full convention.

- **`cosSimExpTens` / `cos_sim_exp_tens` — unified dispatch.** The function now accepts five input forms via type dispatch on its first argument: a single density struct (existing scalar SA / MA path), raw arguments for a single multiset (existing scalar SA / MA path), a cell array (MATLAB) or list (Python) of density structs (new "list mode" — returns a same-length cell / list of per-pair similarities), a 2-D pitch matrix with both dimensions > 1 (new "batched-raw mode" — rows are paired multisets, returns a length-`nRows` vector of similarities), and the existing MA cell-of-arrays raw form (unchanged). The Option II shape rule applies to list mode: a length-1 list returns a length-1 cell / list, never a scalar. Backward compatibility is preserved exactly: every v2.0 calling form produces byte-identical results. Row-vector and column-vector inputs continue to dispatch to the existing scalar SA raw path. The list and batched-raw modes are additive and mutually exclusive with the existing scalar / MA dispatches based on input shape.

- **`evalExpTens` / `eval_exp_tens` — unified dispatch.** Five input forms via type dispatch on the first argument: a single density struct, raw arguments for a single multiset, a cell / list of density structs (returns same-length cell / list of per-density value vectors), a 2-D pitch matrix (rows are multisets, returns an `nRows`-by-`nQ` matrix of values; NaN-padded rows handled identically to `batchCosSimExpTens`), and the existing MA cell-of-arrays raw form. Option II shape rule applies in list mode. Backward compatibility is preserved exactly. In list mode, the `X` argument is broadcast to all densities by default; passing a length-`n` cell of per-density query matrices treats each entry as the `X` for the corresponding density (disambiguated by element type for SA densities).

- **`entropyExpTens` / `entropy_exp_tens` — unified dispatch.** Symmetric additions to `cosSimExpTens` and `evalExpTens`: list mode (cell / list of density structs returns cell / list of entropies, Option II shape rule) and batched-raw mode (2-D pitch matrix returns `nRows`-by-1 vector of entropies; NaN-padded rows handled; rows with fewer than `r` valid pitches return `NaN`). Name-value arguments (`'normalize'`, `'base'`, `'nPointsPerDim'`, `'xMin'`, `'xMax'`, `'gridLimit'`) are forwarded to per-row computations.

- **List-mode broadcasting.** Either operand of `cosSimExpTens` may be a single density struct paired with a cell array (MATLAB) or list (Python) of density structs; the single struct is broadcast against every entry of the cell / list, returning a 1-by-`n` cell / array of similarities (Option II shape rule preserved: a length-1 cell returns a length-1 cell). The pairwise and length-mismatch error paths are unchanged. The `'mode'` `'cartesian'` shape supported by Python `cos_sim_exp_tens` for full list × list cross-products is *not* part of MATLAB list mode; MATLAB list mode remains pairwise-only (with scalar broadcast as the single new shape).

- **Batched-raw broadcasting.** When one of `P1`, `P2` is an `M`-by-`K` matrix (`M > 1`) and the other is a vector of length `K` (1-D, `1`-by-`K` row, or `K`-by-`1` column in MATLAB; 1-D or `(1, K)` 2-D in Python), the vector is broadcast across the matrix's `M` rows in NumPy / MATLAB implicit-expansion style, and the corresponding weights argument is broadcast in lockstep when non-empty. Eliminates the `repmat(refPitches, M, 1)` / `np.tile(ref_pitches, (M, 1))` idiom for the common "compare one reference multiset against many candidates" use case. Mismatched row counts (when neither operand is broadcastable) raise `cosSimExpTens:rowMismatch` (MATLAB) or `ValueError` (Python) with a clear message. Backward compatibility is preserved: explicitly tiled `M`-by-`K` inputs continue to return byte-identical results.

- **`tensorHarmonicity`, `templateHarmonicity`, `virtualPitches` — batched-input dispatch.** Each function now accepts `p` as a 2-D `nRows`-by-`K` matrix with both dimensions > 1, treating each row as a separate multiset and returning per-row results. `tensorHarmonicity` returns an `nRows`-by-1 column vector of harmonicities. `templateHarmonicity` returns `hMax` and `hEntropy` each as an `nRows`-by-1 column vector. `virtualPitches` returns `vp_p` and `vp_w` each as a 1-by-`nRows` cell array of column vectors — cell-of-arrays output is used because the cross-correlation profile length varies per row (depending on the chord's pitch range plus margin), so a numeric matrix alignment is not natural. NaN-padded rows are accepted (NaN entries dropped per row, consistent with `batchCosSimExpTens`); rows with fewer than the minimum required valid pitches yield `NaN` (or empty cell entries for `virtualPitches`). The scalar (vector input) path is unchanged and produces byte-identical results to v2.0. The `p (:,1)` argument-block validation has been relaxed to `{mustBeNumeric}` to admit matrices; row vectors and column vectors continue to dispatch to the scalar path. The `template_harmonicity_formulation_review.md` companion document records known limitations of the `templateHarmonicity` measures (interval-multiset symmetry of chord inversions; single-pitch / H1 hijacking at high spectrum-weight exponents; high-harmonic-density hijacking at low ρ with large N) which apply equally to scalar and batched calls.

- **`spectralEntropy` / `spectral_entropy` — 2-D batched dispatch.** Argument shape relaxed to accept a 2-D `(M, K)` pitch matrix in addition to the original 1-D form. Rows are chords; the return is a length-`M` column vector of per-row entropies. NaN-padded rows are accepted (rows with no valid pitches return `NaN`). Per-row dedup uses the v2.1 canonical-form key with `r=1`, `is_rel=true` (the function transposes internally), `is_per=false` — symmetry-equivalent inputs (transposed copies, permutations) share one cached entropy. Numerical results in scalar mode are unchanged.

- **Tier-1 batched dispatch (DFT-equivariant family): `dftCircular`, `meanOffset`, `edges`, `projCentroid`, `circApm`.** All five circular functions now accept a 2-D `(M, K)` pitch matrix in addition to their original 1-D form, and return 1-by-`M` cell arrays (MATLAB) / length-`M` lists of arrays (Python) for each output. NaN-padded rows are accepted; rows with no valid pitches give empty cell entries. Per-row dedup uses a canonical key built from sorted modular pitches plus matching weights, collapsing **permutation** and **period-equivalent** inputs onto one cached set of outputs. Dedup over **transposition is *not* applied** in this release — the DFT family is transposition-equivariant rather than invariant, and the per-output post-transforms required for full transposition dedup are non-trivial (especially for the query-grid functions whose outputs depend on user-supplied `x`); kept as a future optimisation. Weights may be `None`, the same shape as `P`, or a length-`K` vector broadcast across rows. For `circApm`, each `R` output is dense `period × period`, so memory scales as `M × period^2`; the docstring flags this and recommends chunked processing for large batches.

- **Tier-2 batched dispatch (structural functions): `coherence`, `sameness`, `nTupleEntropy`.** All three set-based circular functions now accept a 2-D `(M, K)` pitch matrix and return per-row results: length-`M` numeric vectors for scalar outputs (MATLAB column vectors / Python ndarrays), plus a length-`M` cell / list for `nTupleEntropy`'s variable-shape `tuples` output. NaN-padded rows are accepted; rows with no valid pitches give `NaN` in the scalar outputs and empty entries in the cell / list. These functions take no `w` argument (they're set-based and reject duplicates), so the batched signature has no weight handling. Per-row dedup keys differ across the three to match what each function's outputs are actually invariant to: `coherence` and `sameness` use the **necklace canonical form** of the cyclic adjacent intervals — collapsing permutation, period, and **transposition** symmetries onto a single cached result, since both functions are fully transposition-invariant on the circle in both `'position'` and `'interval'` modes. `nTupleEntropy` uses sorted-modular only (permutation + period); its `H` value is transposition-invariant but its `tuples` output reflects the input's cyclic ordering from sort-min and so differs across transposed inputs, which would break the dedup contract.

- **Tier-4 batched dispatch (Monte-Carlo functions): `balanceCircular`, `evennessCircular`.** Both functions now accept a 2-D `(M, K)` pitch matrix and return per-row `nRows`-by-1 column vectors (MATLAB) / length-`M` ndarrays (Python), with optional second output for per-row standard deviations. NaN-padded rows are accepted; rows with no valid pitches give `NaN` entries. New name-value pair `rngScope` (default `'canonical'`) controls how the per-row RNG seed is derived from the base `rngSeed` when `sigma > 0`: `'canonical'` derives each row's seed from the canonical-form key via FNV-1a hash, so canonical-form-equivalent rows share an identical Monte Carlo realisation and benefit from caching; `'row'` derives each row's seed from the row index, giving independent reproducible realisations per row and disabling caching. When `rngSeed` is empty, a session-random base seed is generated once per batched call so within-call dedup remains reproducible while across-call results differ. Per-row dedup uses sorted-modular canonical key (permutation + period). The same FNV-1a hash function is implemented identically in MATLAB and Python so a given canonical key produces the same derived seed in both languages.

### Changed

- **Python `mpt` package version bumped to `2.1.0`** (`__version__` and `pyproject.toml`).

- **`nTupleEntropy` / `n_tuple_entropy` refactored as a thin wrapper.** Internally now calls the `differenceEvents` $\to$ `bindEvents` $\to$ `buildExpTens` $\to$ `entropyExpTens` pipeline. With default arguments (`sigma = 0`, `nPointsPerDim = period`, `normalize = true`) it exactly replicates the discrete n-tuple entropy of Milne & Dean (2016) byte-for-byte; existing call sites at `sigma = 0` are unaffected. New optional name-value pairs expose the underlying flexibility: `nPointsPerDim` controls the entropy-evaluation grid resolution per dimension (the integer-step grid by default, finer for better resolution of smoothed densities). For non-integer values, weighted events, non-periodic domains, or to obtain the n-tuple density itself for similarity comparison and other MAET operations, call the primitives directly. **Numerical change at `sigma > 0`.** As described above under *Added — Soft (`sigma > 0`) structural measures*, the new `sigmaSpace` flag changes the default semantics of `sigma` at `sigma > 0`: v2.1.0's default `sigmaSpace = 'position'` treats `sigma` as positional uncertainty on each event, with derived steps inheriting variance $2\sigma^2$ per slot. v2.0.0's effective semantics treated `sigma` as independent per-step uncertainty, equivalent to `sigmaSpace = 'interval'`. The two coincide at `sigma = 0`. To recover v2.0.0 numerical results at `sigma > 0`, pass `sigmaSpace = 'interval'`. See [MIGRATION.md](MIGRATION.md) for a worked example.

- **`bindEvents` / `bind_events` documentation.** Added a clarification to the `circular` argument: it describes the *event sequence* (whether the last event connects back to the first), and is independent of the *positional periodicity* set in `buildExpTens` via its `isPer` / `period` arguments. Both combinations are meaningful: a non-circular sequence on a periodic domain (a non-cyclic motif living in pitch-class space), and a circular sequence on a linear domain (a cyclic rhythm represented in linear time, e.g., for windowed analysis). The two flags are orthogonal. No behavioural change — clarification only.

- **`estimateCompTime` / `estimate_comp_time` — new `minPrintSec` parameter, defaulting to `10` s; `Ctrl+C` and print thresholds collapsed.** The function gains a fifth optional argument (`minPrintSec` in MATLAB / `min_print_sec` in Python). Estimates below the threshold are silent even when `verbose` is true; the default of 10 s is chosen so that sub-10 s waits are their own diagnostic and only genuinely-actionable workloads earn screen real estate. The previous separate "`Ctrl+C to cancel` suffix above 2 s" threshold has been collapsed into the same parameter — every printed estimate now carries the cancellation reminder by construction. The change is uniform across all callers (`evalExpTens`, `cosSimExpTens`, `spectralEntropy`, `templateHarmonicity`, `virtualPitches`, and any user code that calls these in tight loops); no caller needs to opt in. Pass `0` to recover the old always-print behaviour, or set higher to surface only the slowest cases. Existing `verbose=false` callers retain full silence (unchanged).

- **New utility: `printBatchedEstimate` (MATLAB) / `maybe_print_batched_estimate` (Python).** Centralises the batched-mode upfront empirical-calibration print used by `templateHarmonicity`, `virtualPitches`, `spectralEntropy`, `entropyExpTens`, and `tensorHarmonicity` batched dispatch helpers. Threshold and formatting are kept consistent with `estimateCompTime`'s scalar print path: 10-s default `minPrintSec` (or `min_print_sec`), every printed estimate carries `(Ctrl+C to cancel)`, and time-formatting uses the same units.

- **`templateHarmonicity` / `template_harmonicity` — `verbose` option and time estimates.** Both languages gain a `verbose` name-value argument (MATLAB) / keyword argument (Python), default `true`, controlling whether the function prints an upfront time estimate — matching the behaviour `evalExpTens` and `cosSimExpTens` already had. Two estimation strategies, one per dispatch shape: scalar mode uses the kernel-only `estimateCompTime` / `estimate_comp_time` micro-benchmark; batched mode uses an empirical calibration that times a small sample of rows and extrapolates. The estimate is suppressed by `verbose=false`. Numerical results are unchanged.

- **`tensorHarmonicity` / `tensor_harmonicity` and `virtualPitches` / `virtual_pitches` — `verbose` option and time estimates.** Both functions gain a `verbose` name-value argument (MATLAB) / keyword argument (Python), default `true`, mirroring the `templateHarmonicity` addition. `tensorHarmonicity` scalar-mode forwards `verbose` to its inner `buildExpTens` call (the dominant cost for tensor harmonicity is template construction, not template evaluation); `virtualPitches` scalar-mode prints a kernel-only `estimateCompTime` estimate covering its two `evalExpTens` workloads. Both batched-mode helpers use empirical calibration. The estimate is suppressed by `verbose=false`. Numerical results are unchanged.

- **`spectralEntropy` / `spectral_entropy` — `verbose` option.** A `verbose` argument (default `true`) controls printing: scalar mode prints a kernel-only `estimateCompTime` estimate (sum of the dominant `evalExpTens` workload, dim=1); batched mode prints an empirical-calibration estimate with warm-up, in the same idiom as `templateHarmonicity` batched.

- **`entropyExpTens` / `entropy_exp_tens` — `verbose` option for SA batched dispatch.** A `verbose` name-value argument (MATLAB) / keyword argument (Python), default `true`, is added to the existing raw SA batched dispatch. When enabled and `M > 1`, the function prints an empirical-calibration upfront estimate. `verbose=false` silences.

- **Internal performance improvement for `r = 1` expectation tensors.** `buildExpTens` (MATLAB) and `build_exp_tens` (Python) now collapse equal-valued slots at build time when `r = 1`, in both the single-attribute legacy path and the multi-attribute (MAET) path. In the MAET case the collapse is applied per-attribute independently — only attributes with `r_a = 1` are collapsed; attributes with `r_a >= 2` in the same event are unaffected. Mathematically exact: the density at `r = 1` depends on the source multiset only through its measure on the value axis, so events with the same value contribute additively to the same Gaussian kernel and can be merged into a single source point with the sum of the original weights. No behavioural change, no API change. Speedup is proportional to the degree of repetition in the input; for probe-tone-style contexts (e.g., where 7 unique context pitch classes are repeated 3 times) the effective speedup on downstream `evalExpTens` and `cosSimExpTens` calls is approximately 9×. Not applied for `r >= 2`: at higher tuple orders the source multiplicity carries information about within-tuple structure (e.g., the `r = 2` relative density at interval 0 receives genuine contributions from pairs of equal-pitched events) and collapsing would alter the density.

### Fixed

- **`entropyExpTens` (MATLAB) / `entropy_exp_tens` (Python) — single-attribute density entropy at `dim > 1`.** Previously, the SA path constructed a 1-D query grid and called `evalExpTens` with a row vector, which errored when `dim > 1` (for example, `r = 2, isRel = false`). ### Performance

### Design notes

**Additivity.** The v2.0.0 single-attribute calling conventions are preserved verbatim: `buildExpTens(p, w, sigma, r, isRel, isPer, period)`, `cosSimExpTens(p1, w1, p2, w2, sigma, r, isRel, isPer, period)`, and friends continue to work unchanged. The multi-attribute calling form is distinguished by passing `p` as a cell array (MATLAB) or list (Python) of per-attribute value matrices, so the single- and multi-attribute paths do not collide.

**Option Z normalisation.** `windowedSimilarity` normalises by the product of the *unwindowed* L2 norms of the two operands (rather than, say, the windowed norm of the context). This makes the profile value at each sweep position reflect both how well the local content matches the query and how much matching content is present. Multiplying either operand's weights by a constant leaves the profile unchanged.

**MaetDensity slot layout.** For a relative group, `buildExpTens` stores the effective-space Gaussian centres using a slot-0-anchored reduction: $v_i = u_{i+1} - u_0$ for $i = 1, \ldots, r-1$. This convention is inherited by all downstream consumers, including the cross-correlation shift lift in `windowedSimilarity`.

**Option II shape preservation.** All polymorphic dispatch paths preserve list shape: a length-1 list returns a length-1 cell / array, never a scalar. This matches NumPy and MATLAB cell-array semantics and makes downstream consumer code (e.g., a loop over the result) robust to single-element batches.

- **`cosSimExpTens` / `cos_sim_exp_tens`** — Fixed incorrect transposition invariance in the periodic relative case (`isPer = true`, `isRel = true`). ## [2.0.0] — 2026-04-05

### Overview

Version 2.0.0 is a major rewrite of the Music Perception Toolbox. Analytical methods have replaced the previous numerical approximations wherever feasible (entropy computation, which has no known closed-form solution for Gaussian mixtures, remains discretized). The expectation tensor core has been restructured around precomputed density objects (`buildExpTens`), with fully vectorized computation and automatic memory-aware chunking. All existing functions have been given clearer names and a consistent interface, and a Python implementation has been added. The v1 dependency on the [Sparse Array Toolbox](https://github.com/andymilne/Sparse-Array-Toolbox) has been eliminated; v2 has no external dependencies.

Accessibility has been substantially improved: every function now includes a full help text with usage examples, a User Guide covers the conceptual foundations and provides a complete function reference for both languages, and nine demo scripts (in both MATLAB and Python) cover all major use cases.

The original `cosSimExpTens` function by David Bulger is preserved with full backward compatibility: the v1 nine-argument calling convention still works unchanged.

### Added

The following functions are entirely new in v2 (no v1 equivalent):

- **`buildExpTens`** — Precomputes an r-ad expectation tensor density object as a struct that can be reused across multiple calls to `evalExpTens` and `cosSimExpTens`.
- **`evalExpTens`** — Evaluates the expectation tensor density analytically at arbitrary query points with automatic memory-aware chunking and three normalisation modes. (Together, `buildExpTens` and `evalExpTens` replace `expectationTensor`, which built a discretized tensor on a grid.)
- **`batchCosSimExpTens`** — Batch cosine similarity of paired pitch multisets with automatic deduplication of repeated pairs, optional spectral enrichment, and progress reporting.
- **`estimateCompTime`** — Micro-benchmark-based computation time estimator, calibrated to the user's hardware.
- **`templateHarmonicity`** — Harmonicity via template cross-correlation (returns both hMax from Milne 2013 and hEntropy from Harrison & Pearce 2020).
- **`tensorHarmonicity`** — Harmonicity via expectation tensor lookup: evaluates the relative r-ad density of a harmonic series at the chord's intervals.
- **`virtualPitches`** — Virtual pitch (fundamental) salience profile via template cross-correlation.
- **`convertPitch`** — Converts between seven pitch/frequency scales (Hz, MIDI, cents, mel, Bark, ERB-rate, Greenwood cochlear position).
- **Python implementation** — A functionally identical Python package (`mpt`) using NumPy and SciPy. Python uses snake_case naming (e.g., `cos_sim_exp_tens`, `add_spectra`); a few names are shortened where the MATLAB suffix is redundant in a package namespace (e.g., `balanceCircular` → `balance`, `evennessCircular` → `evenness`). See the [User Guide](USER_GUIDE.md#4-api-conventions-matlab-vs-python) for the full mapping and calling convention differences.

### Added — Documentation

- **[User Guide](USER_GUIDE.md)** — Conceptual overview of the theoretical foundations, a complete function reference for both MATLAB and Python (with API convention mapping), worked examples, and demo descriptions.
- **Docstring examples** — Every function includes a full help text with runnable usage examples.
