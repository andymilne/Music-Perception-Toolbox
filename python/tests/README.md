# Python test suite

The full Python suite lives under `python/tests/` and is run with `pytest`. Tests cover both correctness (numerical agreement with closed-form expectations and with the MATLAB implementation where applicable) and dispatch behaviour (path selection, kernel-precision controls, cancellation guards).

## Running the suite

From the `python/` directory:

```bash
# Full suite, default settings (~3-4 minutes on a recent laptop)
pytest tests/ -q

# Single file
pytest tests/test_maet.py -q

# Single test, with full traceback
pytest tests/test_maet.py::TestMAET::test_ma_entropy_sa_equivalence_periodic --tb=long

# Stop on first failure
pytest tests/ -q -x

# Show test progress (per-file rather than per-test)
pytest tests/ --tb=line
```

The test suite expects the `mpt` package to be importable. Install it in editable mode (`pip install -e .` from the `python/` directory) and verify with `python -c "import mpt; print(mpt.__version__)"`.

## Layout

Tests are flat (no subdirectories) and named by topic:

- `test_maet.py`, `test_lazy_density.py`, `test_lazy_density_ma.py`, `test_centre_scalar_broadcast.py` — multi-attribute tensor density and lazy evaluation
- `test_eval_*.py` — `eval_exp_tens` paths (centres / orbit / fast), dispatcher routing, unified raw-array signature
- `test_cos_sim_*.py`, `test_batch_cos_sim_thinning.py` — `cos_sim_exp_tens` paths, polymorphic forms, canonical-form dedup
- `test_dispatcher*.py` — path-selection cost model and timing probes
- `test_windowed_*.py`, `test_window_*.py` — `window_tensor`, `windowed_similarity`, cross-correlation
- `test_circular*.py`, `test_balance_sigma.py`, `test_evenness_sigma.py`, `test_*_sigma_space.py`, `test_dft_circular_simulate.py`, `test_proj_centroid_sigma.py` — DFT, scale-structure, and pulse-level circular measures
- `test_ma_*.py`, `test_orbit_*.py`, `test_tier*.py`, `test_mobius*.py` — orbit-table / Möbius IP paths, including cross-validation against the toolbox
- `test_entropy*.py`, `test_ntuple_entropy_sigma_space.py`, `test_renyi2_entropy.py` — Shannon and Rényi-2 entropy
- `test_harmony*.py`, `test_tensor_harmonicity_orbit.py` — consonance and harmonicity measures
- `test_continuity.py`, `test_seq_weights.py` — ordered-sequence utilities
- `test_simplex_vertices.py`, `test_convert_pitch.py`, `test_add_spectra.py`, `test_kernel_truncation.py`, `test_cross_language_golden.py` — utility, kernel-precision, and MATLAB-vs-Python golden tests
- `test_method_keyword.py`, `test_wrapper_routing.py`, `test_input_validation.py` — public API edge cases

## Memory-aware chunking

A small number of tests allocate large kernel matrices to verify scaling behaviour or to cross-validate against a brute-force reference. On a memory-constrained machine (≲ 4 GiB free), running the full suite in one `pytest` invocation can OOM. The workaround is to run the suite as a sequence of smaller invocations:

```bash
# Run each test file separately, stopping on OOM
for t in tests/test_*.py; do
    timeout 60 pytest "$t" -q --tb=no
done
```

The single test that reliably OOMs in a sandboxed environment is:

- `tests/test_cossim_centres_routing.py::test_truncation_speedup_at_larger_k`

This is a benchmark-style test that measures the speedup of truncated-Gaussian kernel evaluation at large K relative to the exact path. It allocates a large kernel matrix by design. The other 6 tests in that file pass under tight memory. To skip just the heavy test:

```bash
pytest tests/test_cossim_centres_routing.py -k "not speedup"
```

## Adding tests

Follow the existing patterns: tests live in `python/tests/` and are picked up automatically by `pytest`. Use module-level docstrings to summarise what each file covers. For numerical tests, prefer `np.testing.assert_allclose` with explicit `rtol` / `atol` to bare `==` comparisons. For golden-value tests against MATLAB output, the cross-language fixtures live in `python/tests/data/cross_language_golden/` (small JSON files generated by hand-run MATLAB scripts; regenerate only when intentionally changing the reference behaviour).

## MATLAB tests

MATLAB tests live in `matlab/tests/` and use MATLAB's built-in `runtests` harness. From the `matlab/` directory:

```matlab
results = runtests('tests')
```

The two language suites are mostly parallel (each numerical claim is tested in both), but each has a small number of language-specific tests covering call-form conventions (struct vs raw arguments, name-value vs positional, etc.). See ARCHITECTURE.md §7 ("Twin-language conventions") for the conceptual scope of what is and is not parallel.
